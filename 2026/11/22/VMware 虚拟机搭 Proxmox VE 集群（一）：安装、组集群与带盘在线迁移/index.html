VMware 虚拟机搭 Proxmox VE 集群（一）：安装、组集群与带盘在线迁移

目标：三台 PVE 节点组成一个集群，每台挂本地 ZFS 盘，验证”带盘在线迁移”，不使用共享存储。
环境：Windows 宿主机 + VMware Workstation 17 + Proxmox VE 9.2.32（Debian 13 trixie，内核 7.0.14-30-pve）。

规划

节点 Hostname IP 系统盘 数据盘
pve1 pve1.lab 192.168.88.11 32 GiB 60 GiB
pve2 pve2.lab 192.168.88.12 32 GiB 60 GiB
pve3 pve3.lab 192.168.88.13 32 GiB 60 GiB

网络使用 VMware NAT（VMnet8），网关 192.168.88.2。静态 IP 要避开 VMware 的 DHCP 池（通常是 .128 到 .254），否则会和自动分配的地址冲突。

系统盘装 PVE，数据盘留空，装完后单独做成 ZFS 池。这样”系统”和”虚拟机磁盘”分离，也方便后面测试迁移。

1. 宿主机准备

嵌套 KVM 要求 VMware 把 VT-x/AMD-V 透传给虚拟机，Windows 上最大的干扰是 Hyper-V。

VMware Workstation 17 即可（个人使用免费）。宿主机建议 16GB 内存以上、8 核、100GB 空闲磁盘。

2. 创建三台虚拟机

项目 配置
客户机系统 Linux → Debian 12/13 64 位
CPU 2 vCPU，勾选”虚拟化 Intel VT-x/EPT 或 AMD-V/RVI”
内存 4096 MB
硬盘 1 32 GiB，SCSI
硬盘 2 60 GiB，SCSI
网络 NAT（VMnet8）
CD/DVD Proxmox VE ISO

每台都要勾选嵌套虚拟化，这是硬性要求。三台配置保持一致。

10. 注意

  • PVE 9 的企业源文件是 pve-enterprise.sources，不是旧版的 .list，旧命令会报 “No such file”。
  • 升级时满屏 “Tried to start delayed item”，是 apt 3.0.3 的已知 bug，升到 3.0.4 后消失。
  • 新内核装好后必须重启才会生效，用 uname -r 和已安装内核对比确认。
  • 迁移报 local cdrom image：PVE 不迁移 local 存储上的 ISO，迁移前先执行 qm set –ide2 none,media=cdrom。
  • 弹出光驱后忘记改 boot order，虚拟机关机后会提示 no bootable device。

11. 后续更新内容（可能）

  • 给关键 VM 配置 pvesr 复制，迁移时只传增量，节点故障也能在对面直接拉起。
  • 部署 Proxmox Backup Server，做一次整机备份与恢复演练。
  • 评估何时需要共享存储：只有要求秒级迁移或自动故障切换时，才值得上 Ceph 副本 2。
